# 給劇本 AI：《寫給未來的我》試玩回饋（第一輪）

這份文件是製作人試玩後的修改需求，以及引擎接下來會新增的欄位。請依照這份文件修改 `examples/寫給未來的我/script.json`，並交出第 6 節列的東西。

格式仍以 `docs/script-format-v1.md`、`script-format-v2.md`、`script-format-v3-voice.md` 為準；本文件第 4 節是**新欄位**（引擎這一輪會實作，先照這裡寫，引擎做好後就會生效；引擎還沒做好之前，這些欄位會被忽略，不會壞掉）。

---

## 1. 最重要的原則：效果出現前，先給玩家心理建設

製作人的意見：玩家第一次遇到某個效果時，常常以為是「程式壞了」。請在**每一種效果第一次出現之前**，用旁白或主角的內心獨白先鋪陳，讓玩家知道「這是主角正在經歷的事」。

- 例：第一次「選項消失」之前，內心獨白：「最近話到嘴邊，常常就不見了。」
- 例：第一次「時間跳躍」之前：「這陣子常常一回神，天就黑了。」
- 例：第一次「文字模糊」之前：「字越來越難看清楚，老花眼鏡又不知道放哪了。」
- 鋪陳要自然，不要直接說出病名或解釋效果。
- 效果本身也要柔和、逐漸加重：同一種效果第一次出現時用在不重要的句子上，之後才用在關鍵時刻。

## 2. 效果的使用規則（修正）

| 效果 | 規則 |
| --- | --- |
| `text_blur`（文字模糊） | **只用在「主角眼睛看到的文字」**：紙條、便利貼、講稿、招牌、手機訊息。**旁白和對白不要用**，旁白必須工整好讀。 |
| `choice_vanish`（選項消失） | 不要每次都用。一幕最多一兩次，用在「想說卻說不出口」的關鍵選擇。 |
| `time_skip`（時間跳躍） | 前面要有鋪陳（見第 1 節）。跳躍後第一句旁白要讓玩家知道過了多久、現在在哪裡。 |
| `desaturate`（褪色） | 可以照用（引擎會讓選項不跟著變淡）。 |

## 3. 具體要改的地方

1. **婚紗店的佳穎手上拿著鑰匙**，很奇怪。立繪要換成適合婚紗店的樣子。
2. **換衣服要換立繪**：「佳穎進去換第二件」之後，立繪應該換成穿新衣服的樣子。做法：在角色的 `expressions` 加上新的表情名稱（例如 `dress2_smile`），台詞的 `expression` 改用它；並在美術需求裡列出要畫的新立繪（檔名 `{角色id}_{表情}`）。
3. **「媽，好看嗎？」不要重複問兩次**：第二件直接接「這件呢？」，然後進入選項。
4. **換背景**：國華說「講稿在包包的夾層」、新娘說「媽，幫我扣項鍊好嗎？」這兩段的背景不符合現實，請改成合理的場景（例如婚禮會場的新娘休息室），並列出新背景的美術需求。
5. **退休歡送會的邀請卡太早可以點**：用物件的 `appearAt`（從本場景第幾句開始可以點，0 起算）調到台詞提到邀請卡的那一句。
6. **旗袍物件**：製作人忘了它的意思。請在交付說明裡解釋這個物件的設計用意；如果意思不清楚，請改寫說明或真相。
7. **第四章（婚禮）**：有一些對話提到的物件（例如點名簿、便利貼），請加成可以點的物件，並附物件圖，讓玩家看得到示意圖。
8. **結局要有說明文字**：每個結局加 `description`（見 4-1）。
9. **有配音的人物對白**：一律寫成一般台詞（`speaker` 是角色），不要寫成選項的提問文字。

## 4. 新欄位（引擎這一輪會實作）

### 4-1 結局說明 `endings[].description`

```json
{ "id": "ending_a", "title": "口袋裡的信", "condition": "...", "scene": "end_a",
  "description": "一到三句，結局畫面上標題下方的說明。說出這個結局的意義，不要只重複劇情。" }
```

### 4-2 互動物件（例如會響的手機）

可以點的物件（`scenes[].objects[]`）多四個選填欄位，讓它變成「一定要點的互動」：

```json
{ "id": "a1_phone", "label": "手機", "x": 0.18, "y": 0.62, "r": 0.06, "appearAt": 3,
  "image": "a1_phone",
  "description": "佳穎傳來的訊息。",
  "required": true,
  "attention": "ring",
  "sfx": "phone_ring",
  "overlayWidth": 0.08 }
```

- `required: true`：劇情走到 `appearAt` 那一句時停住，玩家點了這個物件、關掉說明卡之後才繼續。
- `attention`：提醒玩家的動畫。`"ring"`＝震動＋發亮（手機、電話、門鈴）；`"glow"`＝柔和發亮（一般重要物件）。
- `sfx`：物件出現時循環播放的音效（`assets/sfx/{名稱}.mp3`），點了就停。
- `overlayWidth`：把物件圖（`image`）直接疊在背景上，寬度是背景寬的比例（0.03～0.3）。不寫就不疊圖，只有點擊區。

這是通用功能：手機、門鈴、電話、鬧鐘都用同一種寫法。

### 4-3 音效出處 `meta.credits`

```json
"credits": [
  { "file": "phone_ring", "title": "Phone Ringing", "author": "作者名稱",
    "license": "CC0", "url": "https://openverse.org/…" }
]
```

引擎會在標題畫面加一個「製作名單」顯示這些出處。

### 4-4 「找找看」時刻 `explore`

很多玩家在手機上玩。有角色在畫面上時，立繪會擋住後面的物件，所以**希望玩家找東西的時候，畫面上不要有角色**。做法是在沒有角色的場景裡，放一句「找找看」：

```json
{ "speaker": "narrator", "text": "廚房裡安安靜靜的。", "explore": "這裡好像有東西可以看看。" }
```

- 這一句出現後，劇情停住，畫面顯示 `explore` 的提示，物件會柔和發亮；玩家找完按「繼續」才往下走（點背景不會跳過）。
- 放在**空場景**（沒有角色立繪）裡、物件都已經出現（`appearAt` 在這句之前）的地方。
- 一個場景最多一次；整部作品約 4～8 次，不要每個場景都有。
- 一定要點的互動（4-2 的 `required`）不要放在角色身後。
- 物件不要放在背景最左、最右邊緣（手機直式要滑動才看得到）；重要物件放在中間 60% 的範圍。

## 5. 音效

引擎**已經支援**台詞音效：任何一句台詞加 `"sfx": "名稱"`，這句出現時播一次 `assets/sfx/{名稱}.mp3`。目前劇本裡一個都沒有用，所以遊戲裡沒有音效。請：

1. 依情境在適合的台詞加 `sfx`（開門、腳步、水壺、手機、人聲嘈雜、掌聲……）。整部作品約 15～30 個，不要每句都有。
2. 到 Openverse（<https://openverse.org/zh-tw>）找音效，**只用 CC0 或 CC BY 授權**（不要用 NC 非商用、ND 禁止改作）。
3. 每個音效寫進 `meta.credits`（第 4-3 節）。
4. 名稱只能用英文小寫、數字、底線（例如 `kettle_whistle`）。
5. 交一份音效清單：名稱、用在哪一句、Openverse 網址、授權、要剪的長度（例如「只要前 3 秒」）。製作人會下載、轉成 mp3、上傳到 `assets/sfx/`。

## 6. 請交付

1. 修改後的完整 `script.json`（只輸出 JSON）。
   - **不要動**：場景與物件的 `id`、已經調好的物件座標 `x`／`y`／`r`、`meta.transition`、`objectHighlight`、`sprite` 等呈現設定、配音編號（除非台詞改了）。
2. 修改清單：每一項改了什麼、在哪個場景。
3. 新的美術需求：新立繪（換裝）、新背景、新物件圖，各寫檔名、要畫什麼、規格。
4. 音效清單（第 5 節）。
5. 台詞有改到的配音編號清單（需要重錄的句子）。
6. 旗袍物件的設計說明（第 3-6 項）。
