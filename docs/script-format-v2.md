# 腳本格式補充說明 v2

這份文件說明 `public/script.json` 在 v1（見 README「如何換腳本」）之上**新增**的欄位。引擎實作時對文件沒寫到的情況所做的決定，整理在最後的「引擎實作補充」。v1 的欄位與規則全部保留不變，舊腳本不用修改也能照常執行。

讀者有兩位：

- **引擎 AI**：照這份文件實作播放器功能與腳本檢查。
- **劇本 AI**：照這份文件撰寫《婚禮前一個月》的完整 JSON。

兩邊只要遵守同一份文件，寫出來的東西就能直接對上。文件沒寫到的情況，引擎 AI 自行決定合理做法，並回頭補進這份文件。

## 新增功能一覽

| # | 功能 | 新欄位 |
| --- | --- | --- |
| 1 | 依條件出現的台詞與選項 | `if` |
| 2 | 可以點來看說明的物件 | 場景的 `objects` |
| 3 | 隱藏的第三個選項 | 選項的 `requires` |
| 4 | 結局的專屬內容 | 不需要新欄位，用 `if` |
| 5 | 記憶對照 | 物件的 `truth`、台詞類型 `memoryReview` |
| 6 | 預設設定 | `meta.settingsDefaults` |

## 1. 條件：`if`

可以掛在**台詞**、**選項**（choice 陣列裡的單一選項）上。值是一段 JavaScript 布林表達式，語法與 `endings[].condition` 相同，另外多兩個輔助函式。

### 可以用的名稱

| 名稱 | 意思 | 範例 |
| --- | --- | --- |
| 數值名稱 | `meta.stats` 裡的每個數值 | `lucidity >= 1` |
| `has("旗標")` | 是否記下過這個旗標 | `has("trust_daughter_pick")` |
| `seen("物件id")` | 是否點過這個物件 | `seen("a1_phone")` |
| `flags` | v1 就有的旗標陣列，保留相容 | `flags.includes("x")` |

`has` 與 `seen` 也要能用在 `endings[].condition`。

### 行為

- **台詞**的 `if` 不成立：整句跳過，不顯示、不寫入對話紀錄、不觸發它的 fx。
- **選項**的 `if` 不成立：這個選項不出現，其他選項照常排列。
- 條件在**播到那一句、或選項出現的那一刻**才判定。
- 「回上一句」回到的是上一句**實際顯示過**的台詞，跳過的句子不算。
- 若一組 choice 裡所有選項的 `if` 都不成立，視為腳本錯誤（腳本檢查要抓出來），執行時直接播下一句。

### 範例

```json
{ "speaker": "husband", "text": "這件是佳穎幫妳選的，很好看。", "if": "has(\"daughter_picked_qipao\")" }
```

## 2. 可以點的物件：`objects`

掛在**場景**上。物件在畫面上以淡淡的熱點出現，點了會跳出一則說明，**不會推進劇情、不算做選擇**。點過之後，物件就被記為 `seen`。

```json
{
  "id": "a1_s01",
  "objects": [
    {
      "id": "a1_phone",
      "label": "手機",
      "x": 0.66, "y": 0.58, "r": 0.04,
      "appearAt": 2,
      "image": "phone_on_table",
      "description": "佳穎傳來新做的指甲，淡粉紅色。這孩子從小就愛漂亮。",
      "truth": "照片下面還有一句：媽，十點喔，不要忘記。她沒有往下滑。",
      "fx": []
    }
  ]
}
```

### 欄位

| 欄位 | 必填 | 說明 |
| --- | --- | --- |
| `id` | 是 | **整份腳本唯一**。同一個實體物件在不同場景出現，要用不同 id（例如 `a1_glasses`、`a2_glasses`）。建議格式：`a{幕}_{物件}`。 |
| `label` | 是 | 物件名稱，兩到四個字。提示功能會顯示成「`label`？」。 |
| `x`、`y`、`r` | 是 | 位置與半徑，規則與 v1 的 hotspot 相同（0–1）。 |
| `appearAt` | 否 | 從本場景第幾句（0 起算）開始可以點。省略為 0。持續到場景結束。 |
| `image` | 否 | 物件圖檔名，放在 `public/assets/fg/{image}.png`。**這張圖要畫真相**（畫面要畫出真相），可以和 `description` 說的不一樣。 |
| `description` | 是 | 點開後顯示的說明，用**淑芬的口吻**。第一幕正確，第二幕起可以說錯，第三幕只剩幾個字。建議 50 字以內。 |
| `truth` | 否 | 這個物件的真相，用於記憶對照。沒有 `truth` 的物件不會出現在記憶對照裡。 |
| `fx` | 否 | 套在說明文字上的效果，目前只支援 `text_blur`、`name_fade`。 |

### 行為

- 只在**台詞播放中**可以點（`phase === 'text'`）；選項出現時熱點暫時隱藏。
- 點開說明時遊戲暫停，再點一下關閉，回到原本那句台詞。
- 同一個物件可以重複點，`seen` 只記一次，但要記下**第一次點的順序**（記憶對照會用）。
- 熱點的明顯程度建議隨退化係數降低：第一幕清楚，第三幕幾乎看不出來。
- 點過的物件寫入對話紀錄，格式例如「（看了手機）」。
- `seen` 狀態要納入「回上一句」的快照。

### 數量建議

第一幕約 4 個、第二幕約 3 個、第三幕 1 個。

## 3. 隱藏的第三個選項：`requires`

掛在**選項**上，值是一個物件 id 或 id 陣列（全部點過才解鎖）。

```json
{
  "prompt": "新娘：「媽，幫我扣項鍊好嗎？」",
  "choice": [
    { "text": "好，媽來。", "effects": { "lucidity": -1 } },
    { "text": "讓爸爸幫妳。", "effects": { "trust": 1, "lucidity": 1 } },
    {
      "text": "先看一下手機裡的照片。",
      "requires": "a1_phone",
      "effects": { "trust": 0, "lucidity": 1 },
      "flags": ["hidden_phone_photo"]
    }
  ],
  "mode": "list"
}
```

### 和 `if` 的差別

| | `if` 不成立 | `requires` 不成立 |
| --- | --- | --- |
| 選項 | 完全不出現 | **出現但灰掉、不能按** |

### 灰掉時顯示什麼

| 設定「隱藏選項提示」 | 顯示文字 |
| --- | --- |
| 關閉（預設） | `你好像記得什麼，但想不起來。` |
| 打開 | 每個未點過物件的 `label` 加問號，例如 `手機？`；多個時以「、」連接 |

不顯示物件在哪一幕、哪個場景。

### 寫作規則

- 有 `requires` 的 choice，**至少要有兩個沒有 `requires` 的選項**。
- 隱藏選項的 `effects` 不可以比另外兩個「明顯更划算」，例如不要給 `trust +1, lucidity +1`。
- 隱藏選項一定要設一個旗標，命名以 `hidden_` 開頭，結局會用它打開專屬內容。
- 全遊戲約 4 條隱藏通道。

---

## 4. 結局的專屬內容

不需要新欄位。在結局場景裡，用 `if` 讓某幾句只在選過隱藏選項時出現：

```json
{ "speaker": "narrator", "text": "手機裡那張照片，是佳穎小時候和外婆的合照。", "if": "has(\"hidden_phone_photo\")" }
```

每條隱藏通道，在三個結局裡都要各有一段專屬內容（一到三句即可）。

## 5. 記憶對照

### 資料來源

玩家點過、而且有 `truth` 的物件，依第一次點的順序，**最多取 4 件**。

### 兩種形式（由設定決定，預設 `inline`）

**`inline`：融入結局。** 在結局場景裡放一個特殊的台詞物件，標記記憶對照要在哪裡播：

```json
{ "memoryReview": { "speaker": "daughter", "intro": "佳穎收拾母親的包包，一件一件拿出來。" } }
```

播到這一行時，引擎先顯示 `intro`（旁白），接著對每件物件依序：

1. 顯示物件圖。
2. 以淡色、劃掉的樣式顯示當時的 `description`。
3. 由 `speaker` 說出 `truth`。

**`page`：結局後的獨立一頁。** 結局場景裡的 `memoryReview` 行直接跳過。結局畫面之後多一頁對照表，左欄 `description`、右欄 `truth`，可以捲動、可以略過。

### 規則

- `memoryReview` 只能出現在 `end_` 開頭的結局場景，每個結局最多一行。
- 玩家沒有點過任何有 `truth` 的物件時，`inline` 只播 `intro` 就結束；`page` 顯示一句「你沒有留下任何記憶。」

## 6. 預設設定：`meta.settingsDefaults`

```json
"meta": {
  "title": "婚禮前一個月",
  "durationMinutes": 15,
  "stats": { "trust": 0, "lucidity": 0 },
  "statRange": { "min": -4, "max": 4 },
  "settingsDefaults": { "hiddenHints": false, "memoryReview": "inline" }
}
```

| 設定 | 值 | 預設 | 設定畫面的文字 |
| --- | --- | --- | --- |
| `hiddenHints` | `true`、`false` | `false` | 隱藏選項提示 |
| `memoryReview` | `"inline"`、`"page"` | `"inline"` | 記憶對照：融入結局／結局後獨立一頁 |

玩家在設定裡改過後，以玩家的選擇為準（存在瀏覽器裡，跟文字速度、音量一樣）。

## 腳本檢查要新增的項目（給引擎 AI）

`validateScript` 要能抓出以下問題：

1. `if` 語法錯誤。
2. `has("x")` 用到的旗標，整份腳本沒有任何選項會設定它。
3. `seen("x")`、`requires` 用到的物件 id 不存在。
4. `requires` 指向的物件，出現在這個選項**之後**的場景（玩家不可能先點到）。
5. 有 `requires` 的 choice，沒有 `requires` 的選項少於兩個。
6. 物件 id 重複。
7. `memoryReview` 出現在非結局場景，或同一結局出現兩次。
8. 一組 choice 的所有選項都有 `if`（有可能全部不出現）。

結局可達性測試也要更新：窮舉時，把「每個物件點或不點」也算進組合裡；組合太多時改成隨機抽樣數千次。

## 文字編輯模式可以改的欄位（給之後做編輯器）

只能改文字，不能改結構：

- 台詞的 `text`
- choice 的 `prompt`、選項的 `text`
- 物件的 `label`、`description`、`truth`
- 結局的 `title`
- `memoryReview` 的 `intro`

`if`、`requires`、`effects`、`flags`、`goto`、座標等結構欄位，在文字編輯模式裡不可修改。

## 劇本 AI 的寫作提醒

- 照 `wedding-outline.md` 的的 16 個場景、20 次選擇撰寫；可以點的物件與 4 條隱藏通道是**新增的**，大綱裡還沒有，要由劇本 AI 設計，並與大綱的小選擇、回扣台詞自然結合。
- 遊玩字數約 3800 到 4500 字，分支總量不超過 11000 字。
- 旗標命名用英文小寫加底線；隱藏選項的旗標以 `hidden_` 開頭。
- 物件 `description` 遵守「越後面越不可靠」，`image` 與 `truth` 永遠是真相。
- 不要寫〈望春風〉的歌詞，只提到歌名或「那段旋律」。

## 引擎實作補充（文件沒寫到的情況）

以下是引擎 AI 實作時自行決定的做法。劇本 AI 寫腳本時也請以這裡為準。

### 1. `if`

- `if` 也可以掛在**整組 choice** 那一行上：不成立時整組選項跳過，直接播下一句。
- 條件執行時出錯（例如呼叫不存在的函式）視為**不成立**，並在瀏覽器主控台警告。`if` 為空字串視為成立。
- 數值名稱不可以叫 `flags`、`stats`、`has`、`seen`；真的撞名時，條件裡請改寫成 `stats.名稱`（腳本檢查會提醒）。
- 有 `if` 的句子若同時掛了 `repeat_line`，重播時不再重新判定（它已經顯示過了）。
- `flat_options` 走的是「第一個**實際出現**的選項」的 `goto`。
- 選項的 `if` 篩掉之後，畫面上每個選項仍保留它在腳本 `choice` 陣列裡的原始位置（測試與開發者面板用 `data-index` 對應）。
- 腳本檢查第 2 條除了 `has("x")`，也會檢查 v1 寫法 `flags.includes("x")`。
