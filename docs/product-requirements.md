# 產品需求書：同理體驗視覺小說引擎

版本 1.0（2026-11-04）。產品名稱暫定，見「待使用者決定」。

---

## 0. 給引擎 AI 的工作說明

- 這份需求書放在 repo 的 `docs/product-requirements.md`，是產品化的總規格。
- 依「階段一 → 階段二」的順序實作。**每一項做成一個 PR**，附上測試，更新 README 與相關文件，全部測試通過才合併。
- 每項都有「驗收條件」，做完要逐條確認。
- 標示 **【待使用者決定】** 的地方不要自己決定，先用最保守的做法（或先留空），並在 PR 說明裡提醒使用者。
- 文件沒寫到的情況，自行決定合理做法，並寫進本文件最後的「實作補充」。
- 既有的 `script.json` 格式（v1、v2、v3 配音）全部保持相容。《寫給未來的我》在每個 PR 之後都要能從頭玩到三個結局。

---

## 1. 產品是什麼

一套**不會做遊戲的人，也能一步一步做出「同理體驗」視覺小說**的工具。玩家用第一人稱經歷某種處境（失智、聽損、憂鬱、轉學、新住民……），介面本身會隨著處境「崩壞」，讓人從裡面體會。

### 產品承諾

> 跟著步驟走，一定可以完成自己的遊戲。

為了兌現這個承諾，**每一步都必須有一條保底路線**：就算使用者不會寫程式、沒有圖、沒有配音、不會架網站，也能走到最後，做出一個能玩、能分享的作品。

### 和其他工具的差異

- 不是通用的視覺小說引擎。核心是**題材包**：每個處境有自己的效果、寫作準則、範本故事。
- 不內建 AI。每一步產生一段提示詞，使用者貼給任何 AI，再把結果貼回來，由引擎檢查。
- 不需要帳號、不需要後端，下載就能用，**可以完全離線**。

---

## 2. 使用者

第一批使用者是**不會做遊戲、想做同理體驗的人**，分兩群。兩群共用同一個引擎，但引導流程與第一版功能不同：

| | A 老師帶學生 | B 醫護、長照、公益組織 |
| --- | --- | --- |
| 誰在做 | 4 人左右的學生小組，老師帶 | 一位專業人員 |
| 時間 | 4 到 6 堂課 | 一兩個月 |
| 作品 | 約 5 分鐘、2 到 3 個場景 | 10 到 20 分鐘 |
| 成敗關鍵 | 夠不夠簡單 | 夠不夠專業、能不能證明有效 |

**先做階段一（兩群共用）。階段二要先做 A 或 B，【待使用者決定】。**

## 4. 發佈形式：從 GitHub 下載就能用

### 4.1 三種取得方式

| 方式 | 給誰 | 內容 |
| --- | --- | --- |
| **線上版** | 想先試試的人 | GitHub Pages：首頁是引導網站，可以玩 Demo、開始做自己的遊戲 |
| **下載版（Release 壓縮檔）** | 一般使用者 | 建置好的檔案，解壓縮後雙擊就能用，**不需要安裝任何東西、不需要網路** |
| **原始碼** | 想改程式的人 | GitHub 的 repo，可以用「Use this template」複製一份 |

### 4.2 repo 結構調整

把「引擎」和「內容」分開，讓下載的人一眼看懂：

```
src/                  引擎原始碼
examples/
  寫給未來的我/       Demo 遊戲（script.json + assets/），失智症題材包的完整範例
templates/
  空白/               空白專案
packs/
  dementia/           失智症題材包（見 5.6）
guide/                引導網站（見 5.1）
docs/                 規格文件與本需求書
```

- 現在的 `public/script.json` 與 `public/assets/` 搬到 `examples/寫給未來的我/`。
- 引擎要能切換載入哪一個專案（範例、範本、使用者自己的專案檔），不再寫死讀 `public/script.json`。
- GitHub Pages 與 Release 壓縮檔都要包含 Demo。

### 4.3 Release 壓縮檔

- 推送版本標籤（例如 `v1.0.0`）時，GitHub Actions 自動建置並附上壓縮檔。
- 壓縮檔內容：
  - `開始.html`：雙擊打開就是引導網站。
  - `玩 Demo.html`：雙擊直接玩《寫給未來的我》。
  - `使用說明.pdf` 或 `使用說明.html`：給完全不懂技術的人看的說明，附截圖。
  - 引擎檔案、Demo 素材、空白範本、題材包。
- 壓縮檔大小要在 README 標示，素材過大時要壓縮（圖片轉 webp、配音維持 mp3）。

### 4.4 離線雙擊開啟（重要）

使用者在沒有網路的電腦上解壓縮，**直接雙擊 html 檔**（網址是 `file://`）就要能用。這是技術上最需要注意的部分：瀏覽器在 `file://` 下會擋掉 `fetch` 讀取本機檔案、ES 模組載入，以及部分 Web Audio 用法。

要求：

- 建置出一個 `file://` 也能跑的版本，例如把程式打包成一般 script、把 Demo 的 `script.json` 打包進 JS。
- 使用者自己的專案：用「開啟專案檔」選擇 `.vnproj`，或存在本機專案（IndexedDB）裡，不依賴 `fetch`。
- 素材：`file://` 下圖片與 `<audio>` 可以用相對路徑載入；如果某些效果（例如音樂走音）在 `file://` 下做不到，要**自動降級**（例如改用合成音或不走音），並在開發者面板顯示「離線模式：某某效果已簡化」，**不可以整個壞掉或出現空白畫面**。
- 如果評估後雙擊開啟有無法克服的限制，在 PR 裡說明，並提出替代方案（例如附一個小型啟動程式），**【待使用者決定】**。

驗收條件：

- [ ] 在斷網的 Windows 與 Mac 上，解壓縮後雙擊 `玩 Demo.html`，用 Chrome、Edge、Safari、Firefox 都能從頭玩到結局，圖片、配音都正常。
- [ ] 雙擊 `開始.html`，能完成引導流程的每一步（AI 步驟除外，見 5.2），存成專案檔，再重新開啟。
- [ ] 降級的效果有清楚列在使用說明裡。

## 5. 階段一：共用核心（兩群都需要）

### 5.1 引導網站（startup 頁）

線上版首頁與 `開始.html` 都是它。

- **首頁**：
  - 一段可以直接玩的《寫給未來的我》片段（約 1 分鐘，例如第一幕的一個場景），讓人先感受「選項在眼前消失」。
  - 一句話說明產品，以及「開始做我的遊戲」按鈕。
  - 流程總覽：每一步要做什麼、大約多久、需不需要 AI。
  - 題材包與範例。
  - 製作紀錄：《寫給未來的我》是怎麼做出來的。
- **引導流程**：一步一步的頁面，畫面上永遠看得到「現在在第幾步、還剩幾步」。
  - 會記住做到哪一步，下次打開可以接著做（存在本機專案裡）。
  - 每一步都可以回到上一步修改。
  - 隨時可以「先跳過，用佔位內容」。
  - 隨時可以切到故事編輯器或試玩。

驗收條件：

- [ ] 一個從沒用過的人，不看任何說明文件，能從首頁走到「開始第一步」。
- [ ] 關掉瀏覽器再打開，回到剛才那一步，內容都還在。

### 5.2 流程步驟與提示詞產生器

完整流程（題材包可以調整每一步的內容）：

1. **選題材包與主題**：選一個處境，寫一句話說明想讓玩家體會什麼。
2. **三個方向的大綱**：產生提示詞，請 AI 寫三個故事方向；使用者選一個或混合。
3. **分場大綱**：場景、選擇、轉折點、結局。
4. **設計表**：可以點的物件、隱藏選項，附自我檢查清單（參考《寫給未來的我》的設計表）。
5. **完整劇本**：產生 `script.json`。
6. **美術需求**：產生給人看的美術說明，以及給生圖 AI 的提示詞表。
7. **素材**：上傳圖片、音樂、配音，或保留佔位。
8. **試玩與修改**。
9. **匯出與發佈**。

每一步：

- 說明這一步要做什麼、為什麼要做。
- **自動產生提示詞**：內含使用者前面填過的內容、題材包的寫作準則、格式規則。一鍵複製。
- 提供一個貼上區，讓使用者把 AI 的回答貼回來。
- 貼回來的內容先檢查（見 5.3），通過才能進下一步。
- 離線時：提示詞照樣產生、照樣能複製，畫面提醒「這一步需要到有網路的地方使用 AI」。

提示詞的來源：把《寫給未來的我》製作時用過的文件改寫成範本，放在題材包裡，包括寫作準則、物件與隱藏通道設計準則、美術需求規則、格式說明。通用的部分放在引擎，題材專屬的部分放在題材包。

驗收條件：

- [ ] 用「失智症」題材包走一次流程，每一步產生的提示詞都包含前面步驟的內容。
- [ ] 把《寫給未來的我》的 `script.json` 貼進第 5 步，能通過檢查。

### 5.3 白話的檢查關卡

- 沿用現有腳本檢查，但每則訊息都要改寫成一般人看得懂的句子，並告訴使用者怎麼修。例如：
  - 現在：`a2_s07.lines[3].choice[1].goto：找不到場景 "a2_s99"`
  - 改成：「第二幕〈點名〉的第 2 個選項，會跳到一個不存在的場景。請把它改成要去的場景，或刪掉這個跳轉。」
- 分成「必須修正」與「建議修正」兩級。只有「必須修正」會擋住下一步。
- 貼回來的不是合法 JSON 時（AI 常多寫說明文字），要能自動抓出其中的 JSON；抓不到時，提示使用者「請 AI 只輸出 JSON」，並附一段可以直接貼給 AI 的修正提示詞。
- 每則錯誤都附一段「請 AI 修正」的提示詞，一鍵複製。

### 5.4 佔位素材保底

- 沒有任何圖片、音樂、配音，也能做完、能玩、能匯出。
- 佔位圖要好看到可以拿去展示：依場景名稱產生一致風格的色塊與構圖，角色用剪影，物件用簡單圖示。
- 素材管理頁顯示「還缺哪些素材」：檔名、用在哪個場景、美術需求的描述，以及已上傳或佔位中的狀態。

### 5.5 匯出與發佈

- **匯出可遊玩版本**：一個壓縮檔，內含雙擊就能玩的 html 與素材，規格同 4.4。可以丟到任何地方、用隨身碟帶著走、放到學校或單位的網站。
- **匯出專案檔**（`.vnproj`，已有）：給之後繼續編輯。
- **發佈到 GitHub Pages 的教學**：圖文步驟，不需要 git。「面板裡直接發佈到 GitHub」需要使用者的 token，有安全疑慮，**本階段不做**。

### 5.5.1 範本專案

- `templates/空白/`：最少的可執行專案。
- 引導流程開始時可以選「從空白開始」或「從範例開始」。

### 5.6 題材包機制

把目前寫死在引擎裡的失智症設計，改成可以切換的題材包。

一個題材包包含：

- `pack.json`：名稱、說明，啟用哪些效果、退化係數的曲線、介面文字（例如「你好像記得什麼，但想不起來」）。
- 寫作準則與各步驟的提示詞範本。
- 範例專案（失智症包用《寫給未來的我》）。
- 注意事項：這個題材要避免的寫法、需要查證的地方、建議諮詢的對象。

規則：

- 失智症包是第一個，內容就是現在的所有設計，行為不變。
- 引擎在沒有題材包時也能運作（所有特殊效果關閉，就是一般視覺小說）。
- 新增題材包不需要改引擎程式。附一份「怎麼做一個題材包」的文件。

驗收條件：

- [ ] 切換到失智症包時，《寫給未來的我》的行為和現在完全一樣。
- [ ] 做一個只有說明文字、沒有特殊效果的測試題材包，引擎照樣能跑。

## 6. 階段二 A：課堂版（老師帶學生）

**是否先做，【待使用者決定】。**

1. **課堂精簡流程**：4 到 6 堂課，每堂一張任務卡，例如第一堂定主題、第二堂寫三個場景。
2. **小作品範本**：約 5 分鐘、2 到 3 個場景、3 到 5 次選擇，照格子填就能完成。
3. **分組角色卡**：編劇、美術、查證、測試員。
4. **查證引導**：每個症狀或處境都要附上資料來源；附「有沒有寫成刻板印象」檢查清單。
5. **免帳號、免安裝**：純瀏覽器，作業以專案檔繳交。
6. **不用學生自己操作 AI 的路線**：未成年人使用 AI 服務常有年齡限制。提供「老師代貼提示詞」與「填空範本，不用 AI」兩種做法。
7. **簡單素材**：佔位圖、手繪拍照上傳（自動裁切與調整大小）、小圖庫。
8. **班級展示**：一次載入多個專案檔輪流玩，附互評表。
9. **給老師的教案與評分規準**。
10. **敏感題材的安全守則**：例如自傷、霸凌，怎麼寫、怎麼引導討論、什麼時候要轉介。

隱私：不收集任何學生資料，所有內容只存在學生自己的瀏覽器與專案檔裡。

## 7. 階段二 B：專業版（醫護、長照、公益組織）

**是否先做，【待使用者決定】。**

1. **完整流程**：5.2 的九個步驟全部開啟。
2. **專家審閱關卡**：內容正確性簽核清單；可以匯出一份「審閱用」的劇本文件（純文字，附場景與選項），讓病友、家屬或顧問在上面留意見。
3. **深度的題材包**：症狀與效果的對照表、寫作準則、常見錯誤。
4. **素材路線**：生圖提示詞表；推薦幾種不需要自己架主機的生圖做法；保留進階使用者用自己主機（例如 ComfyUI）的工具與說明，放在 `tools/advanced/`，標明為選用。
5. **配音指南**：什麼時候需要配音、怎麼錄真人參考音、AI 配音的限制（例如目前難以做出道地的台灣腔）。
6. **正式發佈**：可以放單位名稱與標誌；結尾可以加一頁資源（求助專線、衛教連結、服務資訊）。
7. **成效評估**：玩前、玩後的簡短問卷（題目可自訂），匿名、只在本機統計，可以匯出成表格。不得送出任何資料到外部伺服器。
8. **無障礙**：字幕、字體大小、色弱友善模式、可以關閉畫面晃動與閃爍效果。
9. **製作紀錄範本**。

## 8. 非功能需求

- **沒有後端**：所有資料只存在使用者的瀏覽器與檔案裡。
- **離線**：除了 AI 步驟，所有功能離線可用（見 4.4）。
- **隱私**：不追蹤、不收集使用資料，不載入外部字型、外部分析工具或外部 CDN（離線也需要這個條件）。
- **瀏覽器**：Chrome、Edge、Safari、Firefox 的最新兩個版本；電腦與平板必須完整可用，手機至少能玩。
- **介面語言**：繁體中文。介面文字集中管理，之後可以加其他語言。
- **無障礙**：引導網站與編輯器可以用鍵盤操作，對比足夠。
- **效果安全**：閃爍、晃動類效果要提供關閉選項，並在開始前提醒。

## 9. 這一版不做的事

- 雲端帳號、線上儲存、一鍵發佈到網站。
- 內建 AI（不串接任何 AI 服務）。
- 多人同時編輯。
- 打包成手機 App 或桌面程式。

### 4.2 repo 結構調整

- 專案資料夾：`examples/{名稱}/` 與 `templates/{名稱}/`，各自有 `script.json` 和 `assets/`（`bg`、`char`、`fg`、`voice`、`music`、`sfx`）。
- 載入哪個專案：網址參數 `?project=examples/寫給未來的我` 或 `?project=templates/空白`；沒有參數時載入 Demo（`examples/寫給未來的我`）。只接受 `examples/`、`templates/` 底下一層的資料夾名稱，其他值一律改回 Demo。本機專案（IndexedDB）仍然優先，`?site=1` 可以略過。
- 建置：`vite-plugin-content.ts` 把 `examples/`、`templates/`、`packs/` 原樣複製到輸出資料夾，並為每個專案產生 `assets/voice/manifest.json`、`assets/sfx/manifest.json`，另外產生 `projects.json`（所有專案的路徑與標題，給之後的引導網站用）。開發模式由同一個外掛直接提供這些檔案。
- `public/` 不再使用。
- 開發模式的「儲存」寫回目前專案的 `script.json`（例如 `examples/寫給未來的我/script.json`）。
- 本機素材層、專案檔的路徑格式不變（`bg/x.webp`）；開發者面板的 GitHub 上傳連結改指到目前專案的 `assets/` 資料夾。

### 4.4 離線雙擊開啟

- 評估結果：**不需要啟動程式**。只要不用 ES 模組、不用 fetch 讀本機檔案，Chromium 在 `file://` 下可以完整執行；音檔改用 `<audio>` 播放。
- 建置：`npm run build` 同時產生 `dist/`（網站）與 `dist-offline/`（離線版，`vite build --mode offline`，見 `vite-plugin-offline.ts`）。
  - 程式打包成 iife，連同 CSS 寫進 html。
  - 每個專案的 `script.json` 與 `voice`／`sfx`／`music` 清單寫進 `window.__VN_EMBED__`（每個 html 都包含全部專案，差別只在預設載入哪一個）。
  - 素材照舊在 `examples/`、`templates/`，用相對路徑載入。
- 離線版目前有兩個入口：`玩 Demo.html`、`空白範本.html`。`開始.html`（引導網站）在 5.1 的 PR 加入；使用說明與壓縮檔在 4.3 的 PR。
- 離線模式（`location.protocol === 'file:'`）的降級：
  - 配音、音效、音樂檔用 `<audio>` 播放（Web Audio 的 `MediaElementSource` 在 `file://` 下會被當成跨來源而沒有聲音，所以不接進 Web Audio）。
  - 音樂走音只有播放速度漂移（`preservesPitch = false`）、音量不穩、偶爾靜音；沒有濾波。
  - muffle 只降低音量。
  - 合成音樂照常（不讀檔）。
  - 上傳的音檔已經解碼過，照常用 Web Audio。
  - 匯出專案檔不含內建素材（讀不到）。
  - 開發者面板顯示「離線模式」與簡化項目（`OFFLINE_LIMITS`）。
- 音樂也有清單了（`assets/music/manifest.json`），線上版也不再為不存在的音樂檔發出 404 請求。
- 網址參數 `?project=` 在離線版只接受內嵌的專案。
- 已驗證：Linux 上的 Chromium（自動測試 `tests/offline.spec.ts`：雙擊開啟、圖片、配音、音樂檔、空白範本玩到結局、開啟專案檔後重新開啟、Demo 玩到結局，且不發任何 fetch）。
- **還沒驗證**：Windows／Mac 實機，以及 Safari、Firefox。Safari 在 `file://` 下的本機檔案限制比較嚴，IndexedDB 也可能不能用（開不了本機專案時遊戲照常能玩，只是不能存）；需要在 4.3 的 PR 前用實機確認。

### 5.6 題材包機制

- 格式見 `docs/packs.md`。`pack.json`：`name`、`description`、`effects`（啟用的效果標籤）、`degradation`（退化係數依幕的曲線，超過的幕沿用最後一個）、`texts`（`forgottenPerson`「那個人」、`forgottenThing`「那個東西」）、`docs`（說明文件檔名）。
- 腳本用 `meta.pack` 指定題材包。**相容性決定**：省略 `meta.pack`＝`dementia`（v1／v2／v3 舊腳本照常有效果）；`null` 或 `"plain"`＝一般故事。需求書說的「沒有題材包時所有特殊效果關閉」由 `plain` 達成。
- 執行時：題材包沒啟用的效果一律不觸發（台詞、選項、物件說明、`repeat_line`、`flat_options`）；開發者面板的「觸發效果」按鈕仍可手動測試任何效果。退化係數改由題材包曲線決定。
- 讀不到題材包檔案時：`dementia` 用內建的舊行為（`LEGACY_PACK`，與 `packs/dementia/pack.json` 相同，測試會比對）；其他代號改用一般故事並在主控台提醒。
- 腳本檢查：用了題材包沒啟用的效果時給「（警告）」，不擋。
- 開發者面板「呈現調整」可以切換題材包（即時生效）；`meta.pack` 視為呈現設定，存檔時允許改變。
- 建置：產生 `packs.json`（清單）；離線版把每個 `pack.json` 內嵌進 html。
- 題材包資料夾裡的 `guide.md`、`cautions.md` 目前只是文件；5.2 的提示詞產生器會讀它們。各步驟的提示詞範本也在那個 PR 加進題材包。
- 範例專案與題材包的關係：Demo 的 `meta.pack` 是 `dementia`，空白範本是 `plain`。

### 5.3 白話的檢查關卡

- 檢查規則仍然只有一份（`validateScript`）。`src/checks.ts` 把每則技術訊息翻成白話（`explain`）：
  - 位置翻成「第二幕〈點名〉第 7 句的第 2 個選項「……」」「結局「三句話」」「遊戲設定」這類說法。
  - 訊息本體用對照表改寫，並附「怎麼修」。
  - 對照表沒有的訊息保留原文，並提示貼給 AI。測試會確認常見的問題都有白話。
- 兩級：
  - 「必須修正」：遊戲會出錯或卡住，例如跳到不存在的場景、條件語法錯、說話的人不存在、缺物件代號、配音編號重複。
  - 「建議修正」：照樣能玩，例如物件太靠邊、旗標沒人設定、表情不在清單、所有 `（警告）`。
  - 只有「必須修正」會擋住（`hasBlocking`）。
- 抓 JSON（`extractJson`）：依序試整段解析 → ``` 區塊 → 第一個 `{` 到對應的 `}`（略過字串裡的括號）→ 把中文引號換掉、去掉結尾多餘的逗號。抓不到時說明原因（空白、找不到、被截斷、格式錯），並附「請 AI 只輸出 JSON」的提示詞（`JSON_ONLY_PROMPT`）。
- 提示詞：每則問題 `fixPrompt`、全部 `fixAllPrompt`，都要求「只修正這些問題、輸出完整 script.json、只輸出 JSON」。
- 畫面：`src/issueview.ts`（故事編輯器、開發者面板共用，之後的引導流程也會用）。故事編輯器新增「貼上劇本」分頁（`checkPastedScript`）。
