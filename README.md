# 失智症第一視角：網頁版視覺小說引擎

讓一般人用第一人稱體驗失智症的視角：記憶錯置、時間混亂、情感逐漸淡漠。

這個 repo 是**與內容無關的引擎**。故事、圖片、音樂都放在資料檔與素材檔裡；換內容只要換檔案，不必改程式。

| 配音總表（每句配音有沒有音檔、試聽、匯出缺檔清單） | <https://cathylab.github.io/dementia-game/play.html?voice=1> |

以前分享的連結（首頁加 `?dev=1`、`?story=1` 等參數）會自動轉到 `play.html`，照樣能用。**只有沒有參數的首頁網址改成引導網站**；要給試玩者直接玩，請用 `play.html` 的連結。

開發者版本和文字編輯器只是在網址後面多一段，給試玩者的連結不會出現這些工具。

- 技術：Vite + TypeScript，純前端、無框架、無後端
- 電腦橫式與手機直式都能玩

找不到圖片、音樂或配音檔時，引擎會用佔位圖、合成環境音代替，或安靜略過配音，所以素材可以一批一批補。

## 快速開始

```bash
npm install
```

```bash
npm run dev
```

開啟終端機顯示的網址（通常是 <http://localhost:5173/>）。

| 指令 | 用途 |
| --- | --- |
| `npm run dev` | 開發伺服器（存檔自動重新整理） |
| `npm run build` | 型別檢查並建置網站版 `dist/` 與離線版 `dist-offline/` |
| `npm run preview` | 預覽建置結果 |
| `npm run typecheck` | 只做型別檢查（含測試檔） |
| `npm test` | 跑 Playwright 測試（會自動建置並啟動預覽伺服器） |

### 引導網站

首頁（`index.html`，離線版是 `開始.html`）是給「想做自己的遊戲」的人看的：

- 一段可以直接玩的《寫給未來的我》片段（婚禮當天的休息室，選項會一個個消失），用遊戲頁的 `?clip=場景&from=第幾句` 做成：按開始直接從那裡開始，離開那個場景時顯示「片段結束」。
- 一句話說明、「開始做我的遊戲」、流程總覽（九個步驟、大約多久、需不需要 AI）、題材包與範例、製作紀錄（`guide/making-of.md`）。
- 「開始做我的遊戲」：從空白或從範例開始，建立本機專案，進入一步一步的引導流程。畫面上方永遠看得到「第幾步、還剩幾步」，可以回上一步、先跳過、打開故事編輯器或試玩；做到哪一步存在本機專案裡，關掉瀏覽器再打開，首頁會有「繼續」。
- 九個步驟：
  1. **選題材包與主題**：作品名稱、題材包、想讓玩家體會的事（一句話）、長度、給誰玩。
  2. **三個方向**：請 AI 寫三個故事方向，貼回來，寫下選定的方向。
  3. **分場大綱**。
  4. **設計表**（物件、隱藏選項、效果表、自我檢查清單）。
  5. **完整劇本**：貼回 script.json，白話檢查，沒有「必須修正」才能「套用到我的專案」。
  6. **美術需求**：可以先寫想要的畫風；提示詞會列出劇本需要的每張圖。
  7. **素材**：打開故事編輯器的素材頁。
  8. **試玩與修改**：試玩、檢查清單、劇本檢查（有「必須修正」時不能下一步）。
  9. **匯出與發佈**：專案檔（之後繼續編輯）、**可以玩的版本**（壓縮檔，見下方）、發佈到 GitHub Pages 的步驟。
- 需要 AI 的步驟（2～6）：每一步都**自動產生提示詞**，一鍵複製，貼給任何 AI，再把回答貼回來。提示詞包含前面所有步驟填的內容、題材包的寫作準則與注意事項（`packs/{id}/guide.md`、`cautions.md`），第 5 步另外附上劇本格式（只列題材包啟用的效果）。貼回來的內容檢查通過，「下一步」才會亮；「先跳過」隨時可以按。離線時提示詞照樣能複製，畫面會提醒到有網路的地方用 AI。

**課堂模式（老師帶學生）**：開始頁的第三個選項。流程改成 6 堂課（每堂約 45 分鐘），每堂一張任務卡：

- 每張任務卡有：這堂課的目標、任務清單（附建議時間與負責的角色，可以打勾）、給老師的提醒、「列印任務卡」（列印時只印卡片）。
- 卡片下面直接嵌入這堂課要用的步驟工具（例如第一堂是「選題材包與主題」）。
- 六堂課：認識同理遊戲・定主題 → 故事骨架 → 寫劇本 → 素材與效果 → 試玩與修改 → 發表（最後一堂可以省略）。
- 預設短篇（約 5 分鐘、2～3 個場景）。每一步都可以不用 AI；要用 AI 時可以由老師代貼提示詞。
- 填的內容和完整的九個步驟共用，「改用完整的九個步驟」隨時可以切換。任務卡內容在 `src/guide/lessons.ts`。

**老師代貼提示詞**：未成年學生使用 AI 服務常有年齡限制。

- 學生在需要 AI 的步驟展開「沒辦法自己用 AI？請老師代貼」，下載**代貼單**（`代貼單-組別-步驟.txt`，裡面有組別、作品、步驟與提示詞），交給老師。組別在第 1 步填。
- 老師打開首頁最下方的「**老師工作台**」（`#/teacher`），一次載入全班的代貼單，逐組「複製提示詞」貼給 AI、把回答貼回來（先看過內容），下載**回覆檔**（或「下載全部回覆」打包成一個壓縮檔）。工作台的內容只存在老師這台電腦的瀏覽器。
- 學生在同一步「讀取老師的回覆檔」，回答自動填進貼上區並檢查（劇本那一步會自動按「檢查」）。拿錯步驟的回覆會被擋下。
- 全部用純文字檔傳遞，沒有網路的教室也能用。格式在 `src/guide/relay.ts`。

**照格子填（小作品範本，不用 AI）**：課堂模式第 2、3 堂的工具（完整模式第 5 步也可以展開「不用 AI：照格子填」）。

- 格子：角色（最多 3 個）、2～3 個場景，每場有時間・地點、地點類型、發生什麼、三句對話、一個選擇（兩個選項各有一句回應，標出哪個「比較靠近」）、這一場的效果（只列題材包有的）；兩個結局。
- 按「產生劇本並套用到專案」：沒填的格子會列出來；產生的劇本先跑白話檢查，再取代專案裡的劇本。之後可以在故事編輯器繼續改。
- 產生方式（`src/guide/grid.ts` 的 `gridToScript`）：每個場景是一幕（崩壞逐場加重）；選「比較靠近」的選項加一分（數值 `close`），一半以上就走結局 1；每個選項的回應用旗標加條件；效果加在面對選擇前的最後一句；背景名稱依地點類型，佔位圖會畫出對應的構圖。

**分組角色卡與查證**：

- 首頁最下方的「分組角色卡」（`#/roles`）：編劇、美術、查證、測試員四張卡，列出每個角色在每一堂要做的事，可以列印發給各組。
- 「資料來源表」：故事裡的每個症狀或處境都寫下來源（名稱、網址、查證日期）。課堂模式第 1、2 堂、完整模式第 1 步可以填。填了之後，之後的提示詞會附上這張表，請 AI 只依這些資料寫。
- 「有沒有寫成刻板印象？」檢查清單：試玩後全組逐條打勾（課堂模式第 5 堂、完整模式第 8 步）。

**手繪拍照上傳・小圖庫**（課堂模式第 4 堂、完整模式第 7 步）：列出劇本要用的背景、角色、物品。

- 畫在白紙上、用手機拍照上傳：立繪與物品會自動去掉白紙背景、裁到畫的範圍、底部貼齊，調成遊戲要的大小；背景會裁成橫的 2304×1080。
- 背景和物品也可以從內建的小圖庫選（教室、客廳、廚房、街道、公園…；鑰匙、相片、手機、時鐘…）。
- 處理好的圖存進本機專案，遊戲裡馬上看得到。

**班級展示與互評**（首頁最下方「班級展示」，`#/showcase`）：老師一次載入全班的專案檔，按「開始玩」輪流在大螢幕上玩（左上角「← 回班級展示」），「下一組」換下一個。每個作品都有互評表（四個項目各三級，加上最有感覺的地方與一個建議），可以下載成試算表，或列印紙本互評表。作品存在展示專用的地方，不會蓋掉這台電腦上自己的專案。

**給老師的文件**（首頁最下方「給老師」，`#/docs`）：教案（5～6 節課）、評分規準（六個向度、四個等級）、敏感題材的安全守則（自傷、霸凌等怎麼寫、怎麼引導、什麼時候轉介）。三份都是草稿，內容在 `guide/teacher/`，請老師與輔導專業審閱後再用。

遊戲本身在 `play.html`。兩頁用同一份程式（`src/main.ts` 依 `<html data-page>` 決定）。

### 專案資料夾

引擎和遊戲內容是分開的：

- `examples/寫給未來的我/`：Demo 遊戲（`script.json` ＋ `assets/`）。
- `templates/空白/`：空白範本。
- `packs/`：題材包（之後加入）。

網站有三個入口：`index.html`＝引導網站（首頁）、`play.html`＝**只有遊戲**（給玩家）、`tools.html`＝**製作者工具**（每個遊戲的開發者面板、故事編輯器、素材、配音總表，以及這個瀏覽器裡的本機專案；離線版是 `開始.html#/tools`）。

遊戲網址沒有參數時載入 Demo；加 `?project=templates/空白` 載入空白範本（只接受 `examples/`、`templates/` 底下的資料夾）。可以和其他參數一起用，例如 `?project=templates/空白&story=1`。遊戲網址預設**永遠是網站上的原版**；瀏覽器裡的本機專案只有網址帶 `?local=1` 時才讀（引導網站的「試玩」「打開故事編輯器」會自動帶；`?site=1` 優先，強制看原版）。

建置時這三個資料夾原樣複製到 `dist/`，並為每個專案產生 `assets/voice/manifest.json`、`assets/sfx/manifest.json`，以及列出所有專案的 `projects.json`。

### 下載版（Release 壓縮檔）

給一般使用者的下載版：到 GitHub 的 **Releases** 下載 `同理體驗視覺小說-版本.zip`（目前約 **9.4 MB**，133 個檔案），解壓縮後：

- `開始.html`：做自己的遊戲（引導網站）
- `玩 Demo.html`：玩《寫給未來的我》
- `空白範本.html`：空白的遊戲
- `使用說明.html`：給完全不懂技術的人看的說明（附截圖，`guide/使用說明.html` 與 `guide/usage/`）

不需要安裝、不需要網路（只有「請 AI 寫」的步驟要到有網路的地方）。

- 自己打包：`npm run package` → `release/同理體驗視覺小說-dev.zip`（內容是 `dist-offline/` 加上使用說明，去掉網站才用的檔案）。
- 發佈：推送版本標籤（例如 `git tag v1.0.0 && git push origin v1.0.0`）時，`.github/workflows/release.yml` 會建置、打包，並建立 GitHub Release 附上壓縮檔。在 GitHub 的 Actions 頁手動執行時只打包（壓縮檔在那次執行的 Artifacts），不會發佈。
- 素材變多時請更新上面的大小；圖片請用 webp、配音用 mp3。

### 題材包

每個處境（失智、聽損……）是一個題材包：`packs/{代號}/pack.json` 決定啟用哪些效果、退化係數怎麼隨幕變化、介面上的特殊文字，旁邊附寫作準則與注意事項。腳本的 `meta.pack` 指定用哪一個：

- `dementia`（失智症）：全部 11 種效果，退化 0 → 0.5 → 1。《寫給未來的我》用它；沒寫 `meta.pack` 的舊腳本也當作它。
- `plain`（一般故事）：沒有特殊效果、沒有退化。空白範本用它；`"pack": null` 也是它。

題材包沒啟用的效果，寫在腳本裡也不會出現（腳本檢查會提醒）。開發者面板「呈現調整」的「題材包」可以即時切換並存檔。怎麼做新的題材包見 [`docs/packs.md`](docs/packs.md)。

### 離線版（雙擊就能玩）

`npm run build` 同時建置兩份：

- `dist/`：網站版（GitHub Pages）。
- `dist-offline/`：離線版。把整個資料夾複製到任何電腦（隨身碟、沒有網路的教室），直接雙擊 html 就能玩，不用安裝、不用網路：
  - `開始.html`：引導網站。
  - `玩 Demo.html`：《寫給未來的我》。
  - `空白範本.html`：空白範本。
  - 兩個檔案都可以在網址加 `?project=…`、`?dev=1`、`?story=1` 等參數。

離線版的做法：程式和樣式直接寫在 html 裡（不用 ES 模組），每個專案的 `script.json` 與音檔清單也寫在 html 裡（不用 fetch），圖片、音檔照舊放在 `examples/`、`templates/`，用相對路徑載入。只建置離線版：`npm run build:offline`。

離線模式下簡化的功能（開發者面板會列出）：

| 功能 | 線上版 | 離線版 |
| --- | --- | --- |
| 配音、音效、音樂檔 | Web Audio | `<audio>` 播放 |
| 音樂走音 | 音高漂移、音量不穩、濾波、偶爾靜音 | 只有速度漂移、音量不穩、偶爾靜音（沒有濾波） |
| 聲音變悶（muffle） | 低通濾波＋降低音量 | 只降低音量 |
| 合成音樂 | 有 | 有（一樣） |
| 匯出專案檔 | 含網站上的素材 | 只含自己上傳或開啟的素材 |
| 存檔 | 本機專案存瀏覽器；其他下載 script.json | 同左 |

本機專案（IndexedDB）在離線版也能用：開啟專案檔後存在這個瀏覽器裡，下次雙擊同一個 html 還在。

第一次在自己電腦跑測試前，需要先下載瀏覽器：

```bash
npx playwright install chromium
```

## 如何換腳本

整個故事就是專案資料夾裡的 `script.json` 這一個檔案（Demo 是 `examples/寫給未來的我/script.json`）。直接覆蓋它即可。

### 格式

```json
{
  "meta": {
    "title": "遊戲名稱",
    "durationMinutes": 10,
    "stats": { "trust": 0, "lucidity": 0 },
    "statRange": { "min": -4, "max": 4 }
  },
  "characters": [
    { "id": "daughter", "name": "小婷", "trait": "總是戴著紅色髮圈", "relation": "女兒" }
  ],
  "scenes": [
    {
      "id": "a1_s01",
      "act": 1,
      "title": "早餐",
      "background": "kitchen_morning",
      "music": "calm_home",
      "foreground": null,
      "ui": {},
      "lines": [
        { "speaker": "narrator", "text": "桌上有兩碗粥。", "fx": [] },
        { "speaker": "player", "text": "她在看我。", "fx": [] },
        { "speaker": "daughter", "expression": "neutral", "gaze": "camera", "distance": "normal",
          "text": "爸，今天記得吃藥。", "fx": ["name_fade"] },
        {
          "choice": [
            { "text": "我知道。", "effects": { "trust": 1 }, "flags": [], "goto": "a1_s02" },
            { "text": "什麼藥？", "effects": { "trust": -1, "lucidity": -1 }, "flags": ["asked_about_meds"], "goto": "a1_s02" }
          ],
          "mode": "list",
          "fx": []
        }
      ],
      "next": "a1_s02"
    }
  ],
  "endings": [
    { "id": "ending_a", "title": "結局名稱", "condition": "trust >= 2 && lucidity >= 1", "scene": "end_a" }
  ]
}
```

### 規則

- **speaker**：`"narrator"`（旁白）、`"player"`（主角內心獨白）或 `characters` 裡的 `id`。
- **lines** 依序播放。遇到 `choice` 會停下來等玩家選；選完套用 `effects`（數值會被夾在 `statRange` 內）與 `flags`，再依 `goto` 跳轉。
- 沒有選項的場景播完後走 **next**。
- **結局判定**：`next` 或 `goto` 寫 `"@ending"`，或非結局場景省略 `next`，就會依序判定 `endings` 的 `condition`，第一個成立者勝出；全部不成立時取最後一條（所以最後一條請寫成 fallback，例如 `"true"`）。接著跳到該結局的 `scene`。
- **結局場景**的 id 以 `end_` 開頭，播完後顯示結局畫面與「回到標題」。
- **condition** 是 JavaScript 布林表達式，可以直接用 `meta.stats` 裡的每個數值名稱（例如 `trust`、`lucidity`），以及 `flags` 陣列（例如 `flags.includes("asked_about_meds")`）。
- 角色台詞的 **expression / gaze / distance** 省略時，沿用該角色上一句的值（預設 `neutral` / `camera` / `normal`）。
- **gaze**：`"camera"` 看著我、`"away"` 轉頭看別處（立繪水平翻轉）、`"other"` 看著另一個人（立繪側移並轉身）。
- **distance**：`"near"` 約 1.25 倍並往下、`"normal"`、`"far"` 約 0.8 倍並往上。
- **choice.mode**：`"list"` 為文字選項列；`"hotspot"` 為畫面上的發光熱點，每個選項多帶 `x`、`y`（0–1，相對整個畫面）與 `r`（半徑，0–1，相對畫面寬度）。滑鼠移上或手機長按顯示選項文字，點一下選擇。
- **foreground**：手持物件圖層的檔名，`null` 表示沒有。
- **music**：字串表示播放該曲；`null` 表示靜音；省略表示沿用上一首。
- 畫面上的立繪是「最後一位說話的角色」；換場景時清空。

### 額外的可選欄位

| 欄位 | 位置 | 說明 |
| --- | --- | --- |
| `prompt` | choice 那一行 | 選項上方的提示文字 |
| `goto` 省略 | 選項 | 不跳場景，繼續播放本場景下一句 |
| `wrongObject` | 台詞 | `wrong_object` 要用的物件檔名（見下方） |
| `timeSkipTo` | 台詞 | `time_skip` 要短暫切換到的背景名稱；省略時隨機挑腳本裡另一個背景 |
| `backTarget` | 場景 | `ui.back` 為 `"wrong_scene"` 時，回上一句會跳到這個場景 |

### 效果標籤（fx）

每句台詞或選項可以掛零到多個。

| 標籤 | 作用 | 掛在 |
| --- | --- | --- |
| `name_fade` | 人名框的名字逐字變成底線，最後變成「那個人」，並露出該角色的 `trait` | 台詞 |
| `text_blur` | 這句文字少數字元（約一成多）變淡或被替換成方塊，文字輕微失焦（柔和，不影響閱讀） | 台詞 |
| `repeat_line` | 這句播完後，隔一兩句無預警再播一次 | 台詞 |
| `choice_vanish` | 選項出現後約每三秒消失一個，剩下的重新排列（list 與 hotspot 都適用） | 選項 |
| `flat_options` | 所有選項同樣灰色、同樣語氣（句尾統一成「。」），點任何一個都走第一個選項的 `goto`（被點的那個選項的 `effects`、`flags` 仍會套用） | 選項 |
| `wrong_object` | 背景上疊一個不該出現的物件（預設 `fg/wrong_object`，可用 `wrongObject` 指定）；若場景有 foreground，改為把手持物件換成 `wrongObject`（預設 `{foreground}_wrong`）。持續到場景結束 | 台詞 |
| `time_skip` | 另一個場景的背景（舊照片色調）約 1.8 秒慢慢浮上來，停約 3 秒，再慢慢淡回原本的背景 | 台詞 |
| `desaturate` | 從這句開始畫面飽和度降低（每次 30%），會累加，不會自己恢復（重新開始遊戲才重置）。只影響畫面，選項與對話框不跟著變淡；掛在選項上也可以 | 台詞、選項 |
| `focus_drift` | 景深對焦從角色慢慢飄到背景，角色變糊 | 台詞 |
| `look_around` | 背景（與立繪）無目的地緩慢左右平移 | 台詞 |
| `muffle` | 音訊套低通濾波並降低音量，台詞也稍微變淡 | 台詞 |

`name_fade`、`text_blur`、`focus_drift`、`look_around`、`muffle` 只持續到下一句；要延長就在連續幾句都掛上。

### 全域退化係數

由場景的 `act` 與題材包的 `degradation` 曲線決定。失智症包：第一幕 0、第二幕 0.5、第三幕 1（第四幕以後維持 1）；一般故事包永遠是 0。它會連續影響：

- 打字速度忽快忽慢、偶爾停頓
- 文字間距隨機抖動
- 背景飽和度降低、背景景深更糊
- 視野暗角加重、畫面輕微晃動
- 音樂走音（音高漂移、節奏不穩、偶爾靜音、音量不穩、濾波）

開發者面板可以手動覆寫。

### 介面覆寫（ui）

場景的 `ui` 欄位可以改寫底部功能列，只對該場景有效，預設全部正常。

```json
{ "ui": { "log": "corrupt", "back": "wrong_scene", "skip": "disabled", "auto": "skips_lines" } }
```

| 功能 | 可用的值 |
| --- | --- |
| `back` 回上一句 | `normal`、`disabled`、`hidden`、`wrong_scene`（跳到場景的 `backTarget`） |
| `auto` 自動播放 | `normal`、`disabled`、`hidden`、`skips_lines`（自動播放時偶爾直接跳過一句） |
| `skip` 快轉 | `normal`、`disabled`（按鈕變灰不可按）、`hidden` |
| `log` 對話紀錄 | `normal`、`disabled`、`hidden`、`corrupt`（隨機刪掉幾句並對人名套 name_fade） |
| `hide` 隱藏介面 | `normal`、`disabled`、`hidden` |
| `settings` 設定 | `normal`、`disabled`、`hidden` |
| `title` 回標題 | `normal`、`disabled`、`hidden` |

### v2 新功能

完整規格見 [`docs/script-format-v2.md`](docs/script-format-v2.md)（v1 的部分另外整理在 [`docs/script-format-v1.md`](docs/script-format-v1.md)）（給劇本 AI 與引擎 AI 共用的文件，最後一節是引擎對文件沒寫到的情況所做的決定）。v1 腳本不用修改也能照常執行。

#### 條件 `if`

台詞、整組 choice、單一選項都可以加 `if`，值是 JavaScript 布林表達式：

```json
{ "speaker": "husband", "text": "這件是佳穎幫妳選的。", "if": "has(\"daughter_picked_qipao\") && trust >= 1" }
```

| 可以用的名稱 | 意思 |
| --- | --- |
| 數值名稱 | `meta.stats` 裡的數值，例如 `lucidity >= 1` |
| `has("旗標")` | 是否記下過這個旗標 |
| `seen("物件id")` | 是否點過這個物件 |
| `flags` | v1 的旗標陣列，例如 `flags.includes("x")` |

- 台詞的 `if` 不成立：整句跳過，不顯示、不寫入對話紀錄、不觸發效果。「回上一句」也會跳過它。
- 選項的 `if` 不成立：這個選項不出現。整組都不成立時直接播下一句。
- 條件在播到那一句（或選項出現）的那一刻才判定。
- `has()`、`seen()` 也能用在 `endings[].condition`。

#### 可以點的物件 `objects`

掛在場景上。物件在畫面上是淡淡的圓圈，點了跳出一張說明卡（有圖、名稱、說明），不推進劇情、不算選擇，點過記為 `seen`。

```json
"objects": [
  { "id": "a1_phone", "label": "手機", "x": 0.66, "y": 0.4, "r": 0.04, "appearAt": 2,
    "image": "phone_on_table", "description": "佳穎傳來新做的指甲。", "truth": "照片下面還有一句：媽，十點喔。", "fx": [] }
]
```

| 欄位 | 必填 | 說明 |
| --- | --- | --- |
| `id` | 是 | 整份腳本唯一 |
| `label` | 是 | 物件名稱 |
| `x`、`y`、`r` | 是 | 物件在**背景圖上**的位置與半徑（0–1，半徑相對背景圖寬度）。熱點會跟著背景平移。`x` 請在 0.1～0.9（背景圖左右邊緣平常在畫面外）、`y` 在 0.92 以下（最下面是功能列） |
| `appearAt` | 否 | 從本場景第幾句（0 起算）開始可以點，持續到場景結束 |
| `image` | 否 | 說明卡上的圖，`{專案}/assets/fg/{image}.webp`（或 .png、.jpg），找不到時用佔位圖 |
| `description` | 是 | 說明卡文字 |
| `truth` | 否 | 真相，給記憶對照用 |
| `fx` | 否 | 只支援 `text_blur`、`name_fade`（名稱變成「那個東西」） |
| `if` | 否 | 條件不成立時物件不出現（寫法和台詞的 `if` 一樣） |
| `required` | 否 | `true`＝一定要點：劇情停在 `appearAt` 那一句，點過、關掉說明卡才能往下 |
| `attention` | 否 | 提醒動畫：`"ring"`＝震動＋發亮（手機、門鈴）、`"glow"`＝柔和發亮。可以不搭配 `required` 單獨用。點過就停 |
| `sfx` | 否 | 物件出現時循環播放的音效（`assets/sfx/{名稱}`），點了就停；缺檔安靜略過 |
| `overlayWidth` | 否 | 把 `image` 疊在背景上（白框、圓角、陰影，像一張示意照片），寬度是背景寬的比例 0.03～0.3；點擊區至少 44px |

**找找看時刻**：台詞加 `"explore": "提示文字"`。這句出現時畫面上方顯示提示和「繼續」按鈕，物件比平常亮；點畫面、空白鍵、快轉都不會往下，按「繼續」才往下。手機直式另外提示「左右滑動看看」。主角的內心獨白也可以掛（獨白會停在畫面上）。

- 手機直式時畫面只看得到背景圖中間一段：玩家左右拖曳畫面就能看到整張圖、找到畫面外的物件（邊緣會有箭頭提示）。
- 只有台詞播放時可以點；選項出現時熱點隱藏。說明卡打開時遊戲暫停，再點一下回到原本那句。說明卡靠畫面下方（不擋角色的臉），手機直式從下方滑出；有圖時可以按「放大」看整張圖。場景開始時先載入物件圖。
- `required` 的物件出現時，手機直式會自動把背景平移到它；玩家想往下時物件會晃一下提醒（「減少動態」設定下不晃）。
- 熱點隨退化係數越來越淡，第三幕幾乎看不出來。
- 每點一次，對話紀錄寫一列「（看了手機）」；`seen` 只記第一次，並保留順序。

#### 隱藏選項 `requires`

掛在選項上，值是一個物件 id 或 id 陣列（全部點過才解鎖）：

```json
{ "text": "先看一下手機裡的照片。", "requires": "a1_phone", "effects": { "lucidity": 1 }, "flags": ["hidden_phone_photo"] }
```

- `if` 不成立：選項完全不出現。`requires` 不成立：選項**出現但灰掉、不能按**。
- 灰掉時顯示「你好像記得什麼，但想不起來。」；設定裡打開「隱藏選項提示」時，改成顯示還沒點過的物件名稱，例如「手機？、照片？」。
- 有 `requires` 的 choice 至少要有兩個沒有 `requires` 的選項；隱藏選項要設一個 `hidden_` 開頭的旗標。
- 結局裡的專屬內容不需要新欄位，用 `"if": "has(\"hidden_phone_photo\")"` 即可。

#### 記憶對照

資料來源：玩家點過、而且有 `truth` 的物件，依第一次點的順序，最多 4 件。在結局場景（`end_` 開頭）裡放一行：

```json
{ "memoryReview": { "speaker": "daughter", "intro": "佳穎收拾母親的包包，一件一件拿出來。" } }
```

| 設定 | 呈現方式 |
| --- | --- |
| 融入結局（`inline`，預設） | 播到這一行時，先由旁白說 `intro`；接著每件物件依序：畫面上方出現物件圖與劃掉的當時說明，再由 `speaker` 說出 `truth` |
| 結局後獨立一頁（`page`） | 這一行直接跳過；結局畫面按「繼續」後多一頁對照表，左欄當時的說明、右欄真相，可以捲動、可以略過 |

沒有點過任何有 `truth` 的物件時，inline 只播 `intro`；page 顯示「你沒有留下任何記憶。」

#### 表情清單 `expressions`

角色可以列出自己有哪些表情，台詞的 `expression` 寫錯（例如 `worrid`）時，腳本檢查會抓出來：

```json
{ "id": "daughter", "name": "佳穎", "expressions": ["neutral", "smile", "worried", "tearful"] }
```

- 沒列清單的角色不檢查，舊腳本照常。
- 立繪找不到時，先改用 `{角色id}_neutral`，再沒有才用佔位圖。所以每個角色**先畫 neutral**，其他表情可以慢慢補。
- 開發者面板的「立繪檢查」會列出還缺哪幾張立繪（只是警告）。

#### 預設設定 `meta.settingsDefaults`

```json
"meta": { "title": "婚禮前一個月", "stats": { "trust": 0 }, "settingsDefaults": { "hiddenHints": false, "memoryReview": "inline" } }
```

| 設定 | 值 | 預設 | 設定畫面 |
| --- | --- | --- | --- |
| `hiddenHints` | `true`、`false` | `false` | 隱藏選項提示 |
| `memoryReview` | `"inline"`、`"page"` | `"inline"` | 記憶對照：融入結局／結局後獨立一頁 |

玩家在設定裡動過的項目會存在瀏覽器裡，以玩家為準；沒動過的項目跟著腳本預設值。

#### 台詞上的 `music`

台詞也可以帶 `music`，播到這句時換曲：

```json
{ "speaker": "narrator", "text": "樂隊換了一首。那段旋律。", "music": "spring_wind" }
```

字串＝換成該曲、`null`＝停止、省略＝不變。

### v3：配音

完整規格見 [`docs/script-format-v3-voice.md`](docs/script-format-v3-voice.md)。

- 台詞的 `voice`、choice 的 `voice`（唸 `prompt`）、物件的 `truthVoice`（記憶對照時唸 `truth`）對應 `{專案}/assets/voice/{編號}.mp3`，找不到再找 `.ogg`。
- **缺檔不是錯誤**：安靜播過，主控台也不會有錯誤。音檔可以分批補。
- 聲音不退化，只有 `muffle` 會讓它變悶。設定畫面有獨立的「配音音量」（`settingsDefaults.voiceVolume`，預設 0.9；0 等於關閉）。
- 自動模式會等聲音播完；快轉不播；回上一句會重播；對話紀錄裡有音檔的句子可以點喇叭重播。
- **配音總表**：網址加 `?voice=1`（或開發者面板的「配音總表」）。列出所有配音句與音檔有無、依角色統計、篩選、試聽、整場試聽，並可匯出缺檔清單 `voice-lines.json` 給語音生成工具。

### 檢查腳本

- 開發者面板最下方的「腳本檢查」會列出找不到的場景、未知的 speaker 或效果、條件語法錯誤等問題（也會印在瀏覽器主控台）。v2 另外檢查：
  - `if` 語法錯誤
  - `has("x")` 用到沒有任何選項會設定的旗標
  - `seen("x")` 用到不存在的物件
  - 一組 choice 的所有選項都有 `if`
  - 物件 id 重複、缺少必填欄位、說明套了不支援的效果、位置太低會被台詞區蓋住
  - `requires` 指向不存在的物件，或物件在這個選項之後才出現（玩家不可能先點到）
  - 有 `requires` 的 choice，沒有 `requires` 的選項少於兩個；隱藏選項沒有 `hidden_` 旗標
  - `memoryReview` 放在非結局場景、同一結局出現兩次、`speaker` 不存在
  - `meta.settingsDefaults` 的值不合法
  - 台詞的 `expression` 不在該角色的 `expressions` 清單裡
  - 另有「立繪檢查」：需要的立繪檔還不存在（警告，不算錯誤）
  - 配音編號重複、choice 有 `voice` 卻沒有 `prompt`、`truthVoice` 掛在沒有 `truth` 的物件上；編號格式不對（警告）
- `npm test` 裡的「腳本檢查」測試會驗證 `examples/寫給未來的我/script.json` 格式正確，並窮舉所有選擇組合（包含每個物件點或不點），確認**每一個結局都有路線可以走到**；狀態太多時改用隨機抽樣五千次。

## 如何換圖（檔名約定）

把圖片放進專案資料夾的 `assets/` 底下對應資料夾（以下寫成 `{專案}/assets/`；Demo 是 `examples/寫給未來的我/assets/`），檔名對上就會自動取代佔位圖。副檔名依序找 `.webp`、`.png`、`.jpg`，**建議用 `.webp`**：同樣畫質，檔案小十倍以上，手機才載得快（背景建議 500 KB 以內）。找不到檔案時才用佔位圖，所以可以一張一張慢慢換。

| 種類 | 路徑 | 建議 |
| --- | --- | --- |
| 背景 | `{專案}/assets/bg/{background}.webp` | 2304×1080（畫面寬度的 1.2 倍，留給視線平移）。16:9 也可以，只是上下會被裁掉一點。手機直式時一次只看得到中間一段，玩家可以左右拖曳看整張圖 |
| 立繪 | `{專案}/assets/char/{角色id}_{expression}.webp` | 透明背景直式圖，例如 1000×1800，腳底貼齊圖片下緣。例：`daughter_neutral.webp`、`daughter_smile.webp`。缺圖時先改用 `{角色id}_neutral` |
| 前景（手持物件） | `{專案}/assets/fg/{name}.webp` | 透明背景，物件貼齊圖片下緣，寬約 900 |
| 錯置物件 | `{專案}/assets/fg/wrong_object.webp` 或 `wrongObject` 指定的名稱 | 透明背景，會被縮到畫面寬度約 14% 疊在背景上 |
| 換掉的手持物件 | `{專案}/assets/fg/{foreground}_wrong.webp` 或 `wrongObject` 指定的名稱 | 同前景 |

`background` 與 `expression` 的名稱就是腳本裡寫的字串，不必另外註冊。

**佔位圖**：沒有圖片也能做完、能玩、能展示。背景依名稱猜場景種類（室內、教室、戶外、舞台、店家；名稱有 night、dusk 等字時是夜晚），用柔和的色塊畫出一致的構圖，左上角有小小的「名稱（佔位）」標籤；角色是剪影（表情畫在臉上）；物品是簡單圖示（依名稱猜：眼鏡、紙張、手機、袋子、戒指、杯子）。同一個名稱永遠畫出同樣的圖。

## 如何換音樂

場景的 `music` 欄位對應 `{專案}/assets/music/{music}.ogg`。

- 找不到 `.ogg` 時會再找 `.mp3`（Safari 舊版不支援 ogg，可兩種都放）。
- 建置時產生 `{專案}/assets/music/manifest.json`（和配音一樣），只請求清單上有的檔案，缺檔時不發請求。
- 兩者都沒有時，改用 Web Audio 程式合成的環境音：依曲名決定調性的長音和弦、低頻持續音、輕微房間底噪與偶爾的高音。
- 音樂會循環播放，換曲時交叉淡入淡出。
- 走音機制同時套用在合成音與真實音檔：真實音檔以播放速率漂移造成音高與速度不穩、音量不穩、低通濾波、偶爾靜音；合成音另外讓每個聲部各自走音、和弦節奏不穩。
- 瀏覽器規定要使用者點擊後才能出聲，所以音樂從按下「開始」後才開始。
- 台詞也可以換音樂：台詞的 `music` 寫曲名＝從這句開始換成這首；寫 `null`＝從這句開始停止。故事編輯器裡每句台詞的「♪ 聲音」可以設定。

## 如何加音效

音效是「某句台詞出現時響一次」的聲音（門鈴、杯子放下、手機震動），不循環，可以和音樂、配音同時出現。

- 台詞加上 `"sfx": "door_bell"`，檔案放在 `{專案}/assets/sfx/door_bell.mp3`（或 `.ogg`）。名稱只能用英文字母、數字、底線、連字號。
- 故事編輯器：每句台詞的「♪ 聲音」→「音效」填名稱，「▶ 聽」可以試聽。
- 開發者面板「上傳素材」選類型「音效」可以先放進遊戲試聽。
- 音量跟著設定裡的「音樂與音效音量」，muffle 效果時也會變悶；不受退化走音影響。快轉時不播。
- 建置時產生 `assets/sfx/manifest.json`（和配音一樣），缺檔時不發請求、沒有聲音。

### 章節卡

每一幕的第一個場景開始前，畫面全黑，顯示「第一章」與大字的時間（例如「婚禮前半年」），約 3 秒後淡出進入場景；點一下、空白鍵或 Enter 可以跳過。

## 開發者面板

預設關閉。

- 按 **`` ` ``**（Esc 下方那個鍵）或 **F8** 開關。
- 網址加 `?dev=1` 會一開始就打開（手機上用這個）。
- 標題列的 **−**（或點「開發者面板」幾個字）把面板收合成右上角的一小條，不擋遊戲畫面；按 **＋** 展開。每個區塊的標題點一下可以摺疊，「全部摺疊／全部展開」一次切換。收合與摺疊的狀態記在這個瀏覽器裡。面板沒有「關閉」按鈕（避免不小心關掉）；要完全隱藏按鍵盤的 `` ` `` 或 F8。

### 呈現調整

面板的「呈現調整」可以邊看畫面邊調，按「儲存調整」寫回 `script.json`（本機 `npm run dev`；線上版下載檔案）：

| 項目 | 說明 | 存在腳本的哪裡 |
| --- | --- | --- |
| 遊戲名稱 | 標題畫面的大字 | `meta.title` |
| 封面、直式封面 | 標題畫面的背景圖（`assets/bg/` 裡的圖名稱）；手機直式可以另給一張，沒給就用封面、以中間為主裁切。上傳用「上傳素材」選背景 | `meta.cover`、`meta.coverPortrait` |
| 章節卡、章節卡大小 | 上下兩行都清楚（預設）、「第一章」最大、小而淡（舊樣式）；整體大小倍數；「預覽」在目前畫面顯示一次 | `meta.chapterStyle` |
| 轉場 | 眨眼（原本）、柔和的眨眼、淡入淡出、模糊對焦；「預覽」可以立刻看一次 | `meta.transition` |
| 物件提示 | 物品本身發亮（預設）或圓圈 | `meta.objectHighlight` |

| 音樂 | 改這個場景要播的曲名 | 場景的 `music` |

`sprite` 的 `scale` 是相對原本全身高度的倍數，`y` 是上下位移（畫面高度的 %，負數往下）。目前的劇本預設是腰上構圖：`{ "scale": 2.2, "y": -95 }`。

### 可以點的物件

面板的「可以點的物件」管理目前場景的物件（只保證電腦上好操作）：

- 下拉選單選物件；「新增物件」在目前這句出現、放在畫面中間（代號 `{場景}_obj{n}`，說明文字到文字編輯器或故事編輯器改）；「刪除」。
- 勾「在畫面上拖曳」：畫面上顯示這個場景的**所有**物件（右上角數字是第幾句出現），直接拖曳改 `x`、`y`；拖曳時不會打開說明卡、不會推進劇情。
- 名稱、大小（`r`）、疊圖寬（`overlayWidth`，拉到最左＝不疊圖）、第幾句出現（`appearAt`，「目前這句」一鍵設定）、一定要點（`required`）、提醒動畫（`attention`）、循環音效（`sfx`）。
- 「儲存物件」寫回 `script.json`（允許新增、刪除物件；線上版下載檔案；本機專案存進專案）。

### 專案檔

面板最上面的「專案」區塊。**專案檔**（`.vnproj`）把劇本和所有圖片、配音、音樂裝在一個檔案裡（內容其實是 zip，就像 PowerPoint 的 .pptx），可以存在電腦、用雲端硬碟傳給別人。

- **匯出專案檔**：下載目前的整個遊戲（含這次上傳的素材與還沒存的修改）。網站上還沒有檔案、目前用佔位圖或合成音的素材會列出數量。
- **開啟專案檔**：改用檔案裡的遊戲，存在這個瀏覽器裡（IndexedDB），重新整理也還在。標題畫面下方會出現「本機專案」標籤。
- **存成本機專案**：把目前網站上的遊戲（含這次上傳的素材）存成本機專案，之後的修改就不會因為重新整理而消失。
- 本機專案模式下：文字編輯和「儲存調整」存進專案（不下載 script.json）；上傳的素材自動存進專案。
- **關閉本機專案**：刪掉瀏覽器裡的專案，回到網站上的遊戲。先匯出專案檔再關。
- 本機專案的網址是 `play.html?local=1`（開啟／存成本機專案後會自動換成這個網址）；沒有 `local=1` 的遊戲網址（例如舊書籤）開的是網站原本的遊戲。
- 本機專案只在這台電腦的這個瀏覽器；換電腦、換瀏覽器或清除網站資料時看不到，要用專案檔帶過去。
- 本機專案缺的素材，會再去網站上目前專案的 `assets/` 找同名檔案。

專案檔內容：

```
project.json   { "format": "vn-project", "version": 1, "title": …, "exportedAt": … }
script.json    劇本
assets/bg/…  assets/char/…  assets/fg/…  assets/voice/…  assets/music/…  assets/sfx/…
```

### 可以玩的版本（給別人玩）

引導流程第 9 步，或開發者面板「專案」的「匯出可以玩的版本」，會下載 `作品名-可以玩的版本.zip`：

```
作品名/
  index.html          放到網站時的首頁
  玩 作品名.html      雙擊就能玩（和 index.html 一樣）
  game/assets/…       劇本用到的圖片與音檔（本機專案上傳的，加上網站上有的）
  說明.txt
```

- 解壓縮後雙擊 html 就能玩，不需要網路；也可以把資料夾裡的全部檔案放到任何網站空間。發佈到 GitHub Pages 的步驟見 [`docs/publish-github-pages.md`](docs/publish-github-pages.md)。
- **itch.io**：第 9 步的「匯出 itch.io 用的壓縮檔」（`作品名-itch.zip`）是給 itch.io 的 HTML 遊戲上傳用：`index.html` 在壓縮檔最外層、只有 `index.html` 與 `game/assets/…`（英數檔名），不用解壓縮直接上傳。步驟見 [`docs/publish-itch.md`](docs/publish-itch.md)。
- 劇本、題材包、音檔清單都寫在 html 裡；**永遠玩自己的故事**，不會被那台電腦瀏覽器裡的本機專案蓋掉。
- 還沒有檔案的素材用佔位圖或合成音。離線版匯出時只放得進自己上傳的素材。
- 引擎程式來自離線版建置：建置時產生 `player-template.html`（網站版與離線版都有），離線版直接讀自己頁面上的程式。

### 上傳素材

面板的「上傳素材」可以把電腦裡的檔案直接放進遊戲試看：

1. 選「類型」：配音、背景圖、立繪、物品圖、背景音樂、音效。
2. 「名稱」列出腳本用到的所有檔名，缺檔的標「（缺）」排在前面。
3. 選檔案。可以一次選多個，檔名要和腳本裡的名稱一樣（例如 `a1_s04_01_clerk.mp3`、`kitchen_morning.png`）；只選一個檔案時可以在「名稱」指定要換掉哪一個，檔名不用對。

放進去後畫面上立刻換掉（背景、立繪、物品圖、配音、音樂）。圖片會自動轉成 webp，最長邊超過背景 2560、其他 2048 會縮小。

開著本機專案時，上傳的素材自動存進專案。網站版時，上傳只在這次開啟的頁面有效，重新整理就消失；可以按「存成本機專案」留下來。要放進網站本身（**網頁版沒辦法直接存進 GitHub**）：按每個檔案下面的「下載 …」拿到改好檔名（圖片已轉好 webp）的檔案，再按「打開 GitHub 上傳頁」，把檔案拖進去、按 Commit changes。配音和音樂要是 `.mp3` 或 `.ogg`。

其他網址參數：`?timescale=0.2` 讓所有動畫與等待變成 0.2 倍時間（測試用）。主控台裡可以用 `__vn.engine`、`__vn.view` 直接操作。

## 文字編輯

不用碰 JSON 也能改台詞。打開方式：開發者面板的「打開文字編輯」，或網址加 `?edit=1`。

- 可以改：台詞、選項提示、選項文字、物件名稱／說明／真相、結局標題、記憶對照的 `intro`。
- 不能改：`if`、`requires`、`effects`、`flags`、`goto`、座標等結構欄位（`if`、`requires` 會唯讀顯示在旁邊）。
- 修改立即套用到遊戲；每句旁邊的「▶ 試播」可以從那一句開始播。
- 「復原」「重做」按鈕，或 Ctrl+Z、Ctrl+Shift+Z、Ctrl+Y。
- **儲存**（或 Ctrl+S）：
  - 本機 `npm run dev`：直接寫回目前專案的 `script.json`（例如 `examples/寫給未來的我/script.json`，會重新排版）。若磁碟上的檔案結構在別處被改過，會拒絕寫入。
  - 線上版：下載修改後的 `script.json`，再用它取代專案資料夾裡的 `script.json`。

## 故事編輯

不用碰 JSON 就能做出整個故事：新增場景、寫台詞、做選項和分支、新增角色和結局。打開方式：開發者面板「編輯故事」區塊的「打開故事編輯」，或網址加 `?story=1`。

- **場景與台詞**：左邊是場景列表（依幕分組），每個場景下面的「→」是它會走到哪裡。右邊編輯選到的場景：
  - 場景設定：標題、代號、第幾幕、章節卡文字、背景（有縮圖）、音樂（沿用上一首／靜音／指定曲名）、播完後到哪個場景。
  - 台詞：選誰說的（旁白、主角內心、各個角色）和表情，打字。每句可以上移、下移、在下面插入、刪除，「▶」從這一句開始試玩。
  - 「♪ 聲音」：這句出現時播的音效，以及「從這句開始」換音樂或停止音樂。
  - 選項：提示文字、每個選項的文字和「→ 去哪裡」（繼續這個場景、某個場景、判定結局）。
  - 效果、配音、條件、數值、旗標等進階設定以唯讀小標籤顯示，編輯時會保留。
  - 「＋ 新增場景」加在選到的場景後面，並自動接進流程（前一個場景 → 新場景 → 原本的下一個）。
  - 刪除場景時，原本會跳到它的地方改成跳到它的下一個場景；結局用的場景不能刪。
  - 改代號時，所有跳到這個場景的地方會一起改（配音檔名不會跟著改）。
- **角色**：名字、特徵（名字淡忘時顯示）、關係、表情清單（立繪檔名 `{代號}_{表情}`）；新增角色要給英文代號。
- **結局**：名稱、條件、結局場景，可以調優先順序；「新增結局」會同時建立一個 `end_` 開頭的結局場景。
- 上方的「腳本檢查」即時列出問題，用白話寫：例如「第二幕〈點名〉第 7 句的第 2 個選項「……」，會跳到一個不存在的場景」，附怎麼修。分成**必須修正**（遊戲會出錯）與**建議修正**；每則可以「跳到這裡」，或「複製請 AI 修正的提示詞」貼給任何 AI。
- **素材**分頁：劇本需要的每一個素材（背景、立繪、物品圖、配音、背景音樂、音效），附用在哪些場景、從劇本推出來的描述（例如物件要畫的真相、配音要唸的台詞）、建議規格，以及狀態：「網站上有檔案」「已上傳」「佔位中」。每個素材可以直接「上傳」放進遊戲；「只看還沒有的」與「複製缺少的素材清單」（可以貼給美術或生圖 AI）。
- **貼上劇本**分頁：把 AI 寫好的 `script.json` 整段貼進來（前後有說明文字、用 ``` 包起來、中文引號、多餘的逗號都會自動處理）。抓不到 JSON 時給一段可以直接貼給 AI 的提示詞；有「必須修正」的問題時不能套用。套用後可以按「復原」回來。
- 復原／重做（Ctrl+Z、Ctrl+Shift+Z）、Ctrl+S 儲存、Esc 關閉。
- **儲存**和文字編輯一樣：本機專案存進瀏覽器裡的專案；`npm run dev` 寫回目前專案的 `script.json`（故事編輯允許改結構）；線上版下載 `script.json`。
- 還沒有：物件位置的拖曳、效果與條件的編輯（請用文字編輯或請劇本 AI 改 JSON）。

## 部署

推到 `main` 時，GitHub Actions（`.github/workflows/deploy.yml`）會自動建置並發布到 GitHub Pages：<https://cathylab.github.io/dementia-game/>

第一次需要在 GitHub 上設定一次：repo 的 **Settings → Pages → Build and deployment → Source** 選 **GitHub Actions**。

`vite.config.ts` 用 `base: './'`，所以建置結果放在任何子路徑都能用；要放到別的主機，上傳 `dist/` 整個資料夾即可。

另外 `.github/workflows/test.yml` 會在每個 PR 與推到 `main` 時跑型別檢查與 Playwright 測試。
